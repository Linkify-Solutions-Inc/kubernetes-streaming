Module 1 — AWS account, access, and not getting a surprise bill

Accomplishes: Produces an expiring, MFA-protected AWS credential on your laptop via IAM Identity Center, a budget alarm, Cost Explorer enabled, and pinned CLI tooling (aws, kubectl, eksctl, helm, k9s) installed.

1.1 — Enable Identity Center and create the user CONSOLE

This part is console-only and done once by whoever owns the AWS account.

  • Sign in to the AWS console as the account root or an existing admin. Set the region selector to us-east-1 before you start — Identity Center is regional and its home region cannot be changed later without deleting the instance.
  • IAM Identity Center → Enable. If the account is not part of an AWS Organization, this creates one with the account as management account. That's expected.
  • Permission sets → Create permission set → Predefined → AdministratorAccess. Set the session duration to 8 hours. (Default is 1 hour, which means logging in repeatedly during a 15-minute eksctl create cluster.)
  • Users → Add user. Username intern, a real email address — the invitation goes there and it's also the MFA enrolment path.
  • AWS accounts → select the account → Assign users → intern → AdministratorAccess.
  • Settings → Authentication → Multi-factor authentication → Edit. Set:
  • Prompt users for MFA: Every time they sign in
  • If a user does not yet have a registered MFA device: Require them to register an MFA device at sign-in
  • Note the AWS access portal URL from the Identity Center dashboard. It looks like https://d-1234567890.awsapps.com/start. You need it in the next step.

The invited user completes the email invitation, sets a password, and enrols an MFA device (any TOTP app).

Log in:

You'll run aws sso login once a day; when the session expires, commands fail with The SSO session associated with this profile has expired.

1.3 — Cost Explorer, on day zero CONSOLE

Billing and Cost Management → Cost Explorer → Launch Cost Explorer

Cost Explorer takes roughly 24 hours to populate and does not backfill from before it was enabled — enable it now, not on day ten.

While in the Billing console, also activate cost allocation tags:

Billing and Cost Management → Cost allocation tags → User-defined cost allocation tags
Find "Project" → Activate

The Project tag won't appear in that list until at least one resource has been tagged with it (comes back after Module 3) — without it, Cost Explorer can't break the bill down by tag.

Module 2 — The VPC

Accomplishes: Adds the two things eksctl's auto-created VPC is missing — an S3 Gateway VPC endpoint on every private route table, and the karpenter.sh/discovery tags on private subnets and the cluster security group — both of which fail silently rather than erroring if skipped.

These commands don't run standalone — they run immediately after eksctl create cluster finishes in Module 3. They're reproduced again under Module 3 §3.4 in actual run order; this section exists so the reasoning has a home.

2.1 — Get the VPC eksctl created

export AWS_PROFILE=linkify-streaming
export AWS_REGION=us-east-1

VPC_ID=$(aws eks describe-cluster --name streaming \
  --query cluster.resourcesVpcConfig.vpcId --output text)
echo "$VPC_ID"

2.2 — Add the S3 Gateway endpoint to every private route table

PRIVATE_RTBS=$(aws ec2 describe-route-tables \
  --filters "Name=vpc-id,Values=$VPC_ID" \
            "Name=tag:Name,Values=*Private*" \
  --query 'RouteTables[].RouteTableId' --output text)
echo "$PRIVATE_RTBS"

aws ec2 create-vpc-endpoint \
  --vpc-id "$VPC_ID" \
  --service-name com.amazonaws.us-east-1.s3 \
  --vpc-endpoint-type Gateway \
  --route-table-ids $PRIVATE_RTBS \
  --tag-specifications 'ResourceType=vpc-endpoint,Tags=[{Key=Project,Value=streaming}]'

$PRIVATE_RTBS is intentionally unquoted in --route-table-ids — the command takes a list and the shell needs to split it. Without this endpoint, every HLS segment written to S3 is billed through NAT at $0.045/GB (~$0.19/hour per live stream).

2.3 — Tag the private subnets for Karpenter

PRIVATE_SUBNETS=$(aws ec2 describe-subnets \
  --filters "Name=vpc-id,Values=$VPC_ID" "Name=tag:Name,Values=*Private*" \
  --query 'Subnets[].SubnetId' --output text)

aws ec2 create-tags --resources $PRIVATE_SUBNETS \
  --tags Key=karpenter.sh/discovery,Value=streaming Key=Project,Value=streaming

2.4 — Tag the cluster security group for Karpenter

CLUSTER_SG=$(aws eks describe-cluster --name streaming \
  --query cluster.resourcesVpcConfig.clusterSecurityGroupId --output text)

aws ec2 create-tags --resources "$CLUSTER_SG" \
  --tags Key=karpenter.sh/discovery,Value=streaming

eksctl applies the kubernetes.io/role/* and kubernetes.io/cluster/* tags itself; karpenter.sh/discovery it does not — missing it means Karpenter logs no subnets matched selector and never launches an instance while pods sit Pending.

Verify — Module 2

1. The S3 route exists in every private route table.

aws ec2 describe-route-tables --route-table-ids $PRIVATE_RTBS \
  --query 'RouteTables[].Routes[?GatewayId!=null && starts_with(GatewayId, `vpce-`)].[DestinationPrefixListId,GatewayId]' \
  --output text

One line per private route table — a missing route table means that subnet's pods pay NAT charges for every byte to S3, silently.

2. Subnet tags are present.

aws ec2 describe-subnets --filters "Name=vpc-id,Values=$VPC_ID" \
  --query 'Subnets[].{Name:Tags[?Key==`Name`]|[0].Value,
                      elb:Tags[?Key==`kubernetes.io/role/elb`]|[0].Value,
                      internal:Tags[?Key==`kubernetes.io/role/internal-elb`]|[0].Value,
                      karpenter:Tags[?Key==`karpenter.sh/discovery`]|[0].Value}' \
  --output table

Every public subnet must show elb = 1. Every private subnet must show internal = 1 and karpenter = streaming.

3. Nodes are in private subnets with no public IP.

aws ec2 describe-instances \
  --filters "Name=tag:eks:cluster-name,Values=streaming" "Name=instance-state-name,Values=running" \
  --query 'Reservations[].Instances[].{Id:InstanceId,Private:PrivateIpAddress,Public:PublicIpAddress,Subnet:SubnetId}' \
  --output table

Public must be None for every node.

4.2 — Give the EBS CSI driver an IAM role

ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)

cat > /tmp/pod-identity-trust.json <<'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "pods.eks.amazonaws.com" },
      "Action": ["sts:AssumeRole", "sts:TagSession"]
    }
  ]
}
EOF

aws iam create-role \
  --role-name streaming-ebs-csi-driver \
  --assume-role-policy-document file:///tmp/pod-identity-trust.json

aws iam attach-role-policy \
  --role-name streaming-ebs-csi-driver \
  --policy-arn arn:aws:iam::aws:policy/service-role/AmazonEBSCSIDriverPolicy

sts:TagSession in the trust policy is required — omitting it lets the association create successfully but credential vending then fails with an unhelpful AccessDenied.

aws eks create-pod-identity-association \
  --cluster-name streaming \
  --namespace kube-system \
  --service-account ebs-csi-controller-sa \
  --role-arn "arn:aws:iam::${ACCOUNT_ID}:role/streaming-ebs-csi-driver"

kubectl -n kube-system rollout restart deploy/ebs-csi-controller
kubectl -n kube-system rollout status deploy/ebs-csi-controller

Existing pods do not pick up a new Pod Identity association automatically — this restart is mandatory.

aws eks list-pod-identity-associations --cluster-name streaming \
  --query 'associations[].[namespace,serviceAccount,roleArn]' --output table

4.3 — gp3 as default, gp2 demoted

Manifest already in the repo at k8s/infra/storageclass-gp3.yaml.

Module 5 — DNS, certificates, load balancer controller

Accomplishes: Delegates a Route 53 subdomain (k8s.linkifysolutions.com), issues a wildcard ACM certificate for it in us-east-1, and installs the AWS Load Balancer Controller (IRSA) and ExternalDNS (Pod Identity).

5.1 — Create the hosted zone

aws route53 create-hosted-zone \
  --name k8s.linkifysolutions.com \
  --caller-reference "streaming-$(date +%s)"

HOSTED_ZONE_ID=$(aws route53 list-hosted-zones-by-name \
  --dns-name k8s.linkifysolutions.com \
  --query 'HostedZones[0].Id' --output text | sed 's|/hostedzone/||')
echo "$HOSTED_ZONE_ID"

aws route53 get-hosted-zone --id "$HOSTED_ZONE_ID" \
  --query 'DelegationSet.NameServers' --output text

5.2 — The one-time change at the parent zone CONSOLE

Done by whoever controls DNS for linkifysolutions.com, not necessarily you:

  • Add one record set at the parent zone: Name k8s, Type NS, TTL 300, Value = the four nameservers from 5.1, one per line.
dig +short NS k8s.linkifysolutions.com

Propagation is minutes, not hours — if nothing resolves after 15 minutes, something is wrong with the record, don't just wait.

5.3 — Request the ACM certificate

CERT_ARN=$(aws acm request-certificate \
  --domain-name "*.k8s.linkifysolutions.com" \
  --subject-alternative-names "k8s.linkifysolutions.com" \
  --validation-method DNS \
  --region us-east-1 \
  --query CertificateArn --output text)
echo "$CERT_ARN"

VAL_NAME=$(aws acm describe-certificate --certificate-arn "$CERT_ARN" --region us-east-1 \
  --query 'Certificate.DomainValidationOptions[0].ResourceRecord.Name' --output text)
VAL_VALUE=$(aws acm describe-certificate --certificate-arn "$CERT_ARN" --region us-east-1 \
  --query 'Certificate.DomainValidationOptions[0].ResourceRecord.Value' --output text)

cat > /tmp/acm-validation.json <<EOF
{
  "Changes": [{
    "Action": "UPSERT",
    "ResourceRecordSet": {
      "Name": "${VAL_NAME}",
      "Type": "CNAME",
      "TTL": 300,
      "ResourceRecords": [{ "Value": "${VAL_VALUE}" }]
    }
  }]
}
EOF

aws route53 change-resource-record-sets \
  --hosted-zone-id "$HOSTED_ZONE_ID" \
  --change-batch file:///tmp/acm-validation.json

Never delete this validation CNAME, not even after the certificate reaches ISSUED — removing it breaks automatic renewal a year later.

aws acm wait certificate-validated --certificate-arn "$CERT_ARN" --region us-east-1
aws acm describe-certificate --certificate-arn "$CERT_ARN" --region us-east-1 --query 'Certificate.Status' --output text

5.4 — AWS Load Balancer Controller (IRSA)

helm repo add eks https://aws.github.io/eks-charts
helm repo update
helm search repo eks/aws-load-balancer-controller --versions | head -5

export LBC_VERSION="<version from helm search, e.g. v2.13.0>"
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)

curl -fsSL -o /tmp/lbc-iam-policy.json \
  "https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/${LBC_VERSION}/docs/install/iam_policy.json"

aws iam create-policy \
  --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file:///tmp/lbc-iam-policy.json

This is the upstream-published policy — do not hand-edit it, and do not substitute AdministratorAccess in its place.

eksctl create iamserviceaccount \
  --cluster=streaming \
  --region=us-east-1 \
